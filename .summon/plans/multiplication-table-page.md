## Goal
Add a dedicated page that renders a times table for a chosen number, defaulting to 22, showing rows `22 × 1 = 22` through `22 × 20 = 440`. A control lets the user change the multiplicand and the table recalculates live. The page is reachable from the app navigation.

## Context note
The project currently reports no existing source files, so steps 1–3 cover baseline scaffolding. If any of these files already exist, extend them in place rather than recreating them, and keep their existing conventions.

## Steps

1. **Verify/create the stylesheet** `src/styles/global.css`.
   - First line must be exactly `@import "tailwindcss";`.
   - Outcome: Tailwind v4 utilities available app-wide.

2. **Verify/create the app entry** `src/main.tsx`.
   - Imports `@/styles/global.css` once, creates the router from the generated route tree, and mounts into `#root`.
   - Outcome: app boots with routing and styling active.

3. **Verify/create the root layout** `src/routes/__root.tsx`.
   - Provides the page shell: a header with a nav containing links to `/` (Home) and `/times-table` (Times Table), plus an `<Outlet />` for page content.
   - Nav links use TanStack Router `Link` with active styling via the `activeProps`/`className` pattern already used in the file, if present.
   - Outcome: a persistent header with working navigation on every page.

4. **Create the calculation helper** `src/lib/multiplication.ts`.
   - Export a function that takes a base number and a row count and returns an array of `{ multiplier, product }` entries.
   - Export a parse/clamp helper that turns raw input text into a safe number: rejects empty string and non-numeric input, clamps to a supported range (e.g. -1000 to 1000), truncates decimals to integers.
   - Outcome: pure, testable logic separated from UI.

5. **Add shared types** `src/types/multiplication.ts`.
   - Define the row entry type used by the helper and the table component.
   - Outcome: single source of truth for the row shape.

6. **Create the number control component** `src/components/NumberPicker.tsx`.
   - Props: current value, change handler, optional min/max.
   - Renders a labelled `<input type="number">`, decrement/increment stepper buttons, and a small row of preset buttons (e.g. 2, 5, 9, 12, 22) that set the value directly.
   - Holds the raw input string in local state so the field can be temporarily empty while typing; commits only valid parsed values upward.
   - Outcome: accessible, forgiving input for choosing the multiplicand.

7. **Create the table component** `src/components/TimesTable.tsx`.
   - Props: base number, row count (default 20).
   - Renders a semantic `<table>` with a caption/heading and one row per multiplier showing the full working: base, `×`, multiplier, `=`, product.
   - Uses tabular/right-aligned numerics and zebra striping via Tailwind; no hover highlight.
   - Outcome: readable, correctly computed table.

8. **Create the route** `src/routes/times-table.tsx`.
   - Exports a TanStack Router file route for `/times-table`.
   - Holds the current number in `useState` initialised to `22`.
   - Renders a page title, `NumberPicker`, and `TimesTable`, wrapped in a centred, max-width container with vertical spacing.
   - Outcome: `/times-table` shows the 22 times table on load and updates instantly when the number changes.

9. **Create/update the home route** `src/routes/index.tsx`.
   - Brief intro plus a prominent link to `/times-table`.
   - Outcome: the feature is discoverable from the landing page.

10. **Do not touch** `src/routeTree.gen.ts` — it is regenerated by the router plugin when the new route file is added.

## Edge cases to handle
- Empty input: field may be blank while typing; table keeps the last valid number rather than crashing or showing `NaN`.
- Non-numeric / partial input (`-`, `.`, `e`): ignored until parseable.
- Zero: valid — every product is 0.
- Negative numbers: valid — products render with the minus sign; layout must not shift.
- Decimals: truncated to an integer on commit.
- Very large numbers: clamped to the supported range so products stay within safe integer range and do not overflow the column width.

## Responsive layout notes
- Page container: full width on mobile with horizontal padding, capped max width and centred on larger screens.
- Control row: stacks vertically on small screens, becomes a single horizontal row from the `sm` breakpoint up.
- Table: full width, comfortable row height on touch, wrapped in a horizontally scrollable container as a safety net for narrow viewports.
- Preset buttons wrap onto multiple lines instead of overflowing.
